# 日本語校正スキル

Markdown ファイル内の日本語テキストを校正し、誤りを修正するスキルである。

## 校正の原則

このスキルが目指すのは「著者の意図を尊重しつつ、明らかな誤りだけを直す」ことである。
文章を「より良く」書き直すのではなく、誤りを「正しく」直すことに徹する。

### 修正する対象

1. **誤字脱字** — 漢字の誤変換、かなの打ち間違い、送り仮名の誤り
2. **文法の誤り** — 助詞の誤用、主述のねじれ、接続の誤り
3. **表記揺れ** — 同一文書内で同じ語が異なる表記で使われている場合（例：「サーバー」と「サーバ」、「行う」と「おこなう」）

### 修正しない対象

- 文体やトーンの変更（である調→ですます調など）
- 表現の改善や言い換え（意味が通じている文は触らない）
- Markdown の構文やフォーマット
- コードブロック内のテキスト
- 英語のスペルチェック（日本語の校正に集中する）
- 著者の意図的な表現（口語体、方言など、文脈から意図的と判断できるもの）

## 校正プロセス

### Step 1: 対象ファイルの特定

対象ファイルは以下のいずれかで決まる：

- ユーザーが明示的にファイルパスを指定した場合 → そのファイル
- hooks から実行された場合 → 変更された `.md` ファイル
- 指定がない場合 → ユーザーに確認する

対象は `.md` ファイルのみ。それ以外のファイルが指定された場合は、Markdown ファイルのみが対象である旨を伝える。

### Step 2: ファイルの読み込みと分析

1. 対象ファイルを Read ツールで読み込む
2. コードブロック（``` で囲まれた部分）を特定し、校正対象から除外する
3. 日本語テキスト部分を抽出し、以下の観点で分析する：
   - 誤字脱字の候補
   - 文法的な誤りの候補
   - 表記揺れの候補（文書全体で統一されているか）

### Step 3: 表記揺れの判定

表記揺れを修正する際は、以下のルールに従う：

- 文書内でより多く使われている表記に統一する
- 出現回数が同じ場合は、JIS規格や一般的な用法に準じた表記を採用する
- 固有名詞や引用文内の表記は変更しない

### Step 4: 修正の適用

1. 修正が必要な箇所を特定したら、Edit ツールでファイルを直接修正する
2. 1つの修正ごとに Edit ツールを実行する（複数箇所をまとめない）

### Step 5: 差分の表示

すべての修正が完了したら、以下の形式で差分を表示する：

```bash
git diff <対象ファイルパス>
```

修正がなかった場合は「修正箇所はなかった」旨を報告する。

## 出力フォーマット

差分表示の後、修正内容のサマリーを以下の形式で出力する：

```
## 校正結果

- 修正箇所: N 件
  - 誤字脱字: N 件
  - 文法の誤り: N 件
  - 表記揺れ: N 件

### 修正内容

| # | 種別 | 修正前 | 修正後 | 理由 |
|---|------|--------|--------|------|
| 1 | 誤字 | 〇〇 | △△ | 漢字の誤変換 |
| 2 | 表記揺れ | サーバ | サーバー | 文書内で「サーバー」が多数 |
```

## hooks での自動実行

hooks として実行される場合：

1. 変更された `.md` ファイルを自動的に検出する
2. 確認なしで校正を実行する
3. 修正があった場合はファイルを直接修正し、git diff 形式で差分を表示する
4. 修正がなかった場合は何も出力しない（サイレント）
